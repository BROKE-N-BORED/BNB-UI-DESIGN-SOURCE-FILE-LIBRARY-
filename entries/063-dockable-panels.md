# 063 — Dockable panels

> Entry 063 — added 2026-11-14 (Drop 6: Structure, comfort, and trust).

*Panels that dock, float, tab together, and split, so the workspace fits the job instead of the other way round.*

**What it is.** A dockable panel is a chunk of the interface, a file tree, a terminal, a layer list, a preview, that the user can move: drag it to another edge of the window, drop it onto another panel to share the space as tabs, split it into a new group, or pull it out to float as its own window, often onto a second monitor. The layout is the user's, not the app's: VS Code lets views and panels be dragged between the Primary Side Bar, the Secondary Side Bar, and the Panel region, and remembers the arrangement across sessions. Blender divides its window into rectangular Areas, each holding one Editor, and groups Areas into Workspaces aimed at one task, modeling, animating, scripting. Obsidian puts every tab in a tab group that can be split right or down, resized by dragging its edge, or dragged out of the window into a pop-out window. DaVinci Resolve takes the opposite, stricter line: its pages have fixed panel sets that you resize and show or hide, save as named layout presets, and spread across two screens with a Dual Screen mode, but the second screen can be resized, not reorganized, and only specific things, a Media Pool bin, the video scopes, can float free. Both shapes count. The point is the same: the person arranges the tools around the work.

**Why it feels good.** A fixed layout makes every job pay for the tools it does not need. A dockable one lets the person put the thing they are looking at next to the thing they are doing, then put it away when the job changes. The good systems share four behaviors. First, dragging shows where the panel will land before you drop it: Obsidian highlights drop zones as you drag, Blender brightens the areas a join will affect, VS Code shows the drop target. Second, grouping is one gesture: drop a view onto another view and they become tabs in one panel, as in VS Code's view groups, Obsidian's tab groups, and Qt's tabified docks. Third, the layout survives: VS Code restores views and floating windows at their saved positions after a restart, Obsidian's Workspaces plugin saves open files, tabs, and sidebar widths and visibility under a name, Resolve saves named layout presets you can load, update, and export to another machine. Fourth, there is always a way back: VS Code has Reset View Locations plus a per-view Reset Location, Resolve has Reset UI Layout, Blender lets you cancel a split or join with Esc or right-click before you release the mouse.

**The numbers.** Panel systems publish few numbers, so most of this entry is mechanism, and the figures below are the ones the sources actually state. VS Code moves its Panel region to four positions, left, right, bottom, or top, and offers four panel alignments, Center, Justify, Left, Right; its editor grid layouts include Two Columns, Three Columns, and Grid (2x2). Qt gives a main window four dock areas, left, right, top, and bottom, and ships with two dock options on by default, AnimatedDocks and AllowTabbedDocks. Resolve documents keyboard shortcuts for up to five layout presets. Blender's maximize shortcut is Ctrl-Spacebar, which fills the window while keeping the editor's menu bar and status bar, and its Focus Mode shortcut is Ctrl-Alt-Spacebar, which hides the Topbar, the Status Bar, and the editor's secondary regions for maximum space. Obsidian's help gives no sizes at all, only the drag, drop-zone, split, and resize behaviors. No source gives a recommended minimum panel size, so this entry sets none; the minimums in Watch out are stated as mechanisms, not figures.

**Where it fits his apps.** ACR: its Main, Controls, Trace, Views, and Analyze windows are already separate, so the honest next step is one main window where the trace log, the resonance chart, and the controls are dockable panels, with the chart able to float to a second monitor and a Reset Layout command in the View menu. Reblend: the 3D viewport is the center and the object list, material editor, and preset picker are the docks, with the material editor the obvious float candidate. Pixel Forge: layers, tools, and presets dock around the canvas, with layers and history tabbed together in one panel. Code Forge: findings, diff, and queue as docks around the file view, so a review can put the diff beside the finding that names it. LYNX SHARE: mixer, clip launcher, and timeline as docks, with the mixer able to float wide on a second screen. GITDATA: the results list and the record detail as a split pair, so a dataset can be read while the list stays visible. MIMIK: the capture library and the preview as docks, with the preview floatable while a capture runs. Qwkhnd does not need this: a single-column triage list has nothing to dock, and adding panels would only add chrome. Qt fit: QDockWidget is built for exactly this, movable, floatable, and closable by default, with tabified docks on by default and nesting opt-in. Qt itself warns that nesting makes drag behavior more complex and less intuitive, so start without it. Turn AnimatedDocks off on his PC: with it cleared, contents snap to their new positions instead of animating, which is the cheap-motion choice and what Qt recommends when widgets are slow to repaint. Persist the layout with saveState and restoreState through QSettings, and give every dock a checkable View menu entry from its toggleViewAction, so a closed panel is always one menu click away. Focus rings on dock tab bars still need a border on :focus, since outline renders 0 pixels in this build.

**Watch out.** A panel system fails in a few predictable ways. Lost panels: a user closes or floats a panel and cannot find it again, so every panel needs a named, checkable View menu entry and a reset-to-default command, the way VS Code and Resolve both provide one. Floating panels off-screen: a panel floated onto a monitor that is no longer connected is stranded, so the reset command must also bring floating panels home, and Resolve's advice to keep separate laptop and dual-screen presets is worth copying. Minimum sizes: a panel squeezed to nothing is a panel that looks broken, so set minimum sizes on the panel's content widget, not on the dock widget itself, because Qt says the dock's own constraints change with its docked state, and a docked panel has no frame and a smaller title bar. Tabbed stacks hide panels: the second tab in a stack is invisible until clicked, so do not tab together two panels the user needs to see at once, and do not let a panel that carries a warning or a live status sit behind a tab. Free docking is not always the answer: Resolve deliberately restricts it, because in color grading a stable, predictable layout matters more than freedom, so match the freedom to the job. And a dock system is not a substitute for a good default: most users never rearrange anything, so the shipped layout has to be the good one, and the docking is for the few who want more.
