# 054 — Starter content and templates

> Entry 054 — added 2026-11-13 (Drop 5: Choices, motion, and craft).

*A new project opens already full of something useful, so the user edits instead of creating from nothing.*

**What it is.** Starter content is a new project that opens pre-filled with a working example instead of a blank page: a demo song in a music app, a sample page in a notes app, a cube and a camera and a light in a 3D app. Templates are the same idea in a choosable form: a gallery of pre-built starting points, one per job, that the user picks and then edits. The two forms differ in who chooses. A single opinionated starter (Blender's startup scene, FL Studio's demo songs) decides for the user: open the app and there is already something real on screen. A template gallery (Figma, Notion) asks the user to pick a starting point first. Both exist to solve the same problem, which is the blank page staring back at someone who does not yet know what the tool is for.

**Why it feels good.** Editing is easier than creating. A pre-filled example shows what the tool does, what a finished thing looks like, and where the controls live, all without a tutorial. The user changes one word, moves one clip, deletes one object, and in doing so learns the editor by using it. A teardown of Notion's onboarding puts the point plainly: the goal is a working artifact within the first 30 seconds, with two example items the user can edit immediately, because editing one item is the activation event, and once they have crossed it, they understand the editor. A blank page, by contrast, asks the user to supply both the idea and the vocabulary at once, which is why so many first sessions end with the tab closed.

**The numbers.** Figma's template gallery lists 300 plus templates made by Figma's own team, with 1,000 plus more from the community. Notion's current first run shows starter pages in the sidebar (Getting Started, Quick Note, Tasks) and a template gallery of 16 plus tiles in the main pane, which the teardown calls a paradox of choice: sixteen tiles, each looking equally valid, no opinionated default. Blender's startup scene is exactly three objects, a cube, a camera, and a light, plus a grid floor and a 3D cursor, and the user can save any scene of their own as the startup file. FL Studio Mobile ships demo songs on its SONGS tab, with a Hide demo songs setting for users who no longer want them. For measuring the technique, the Notion teardown proposes activation as 3 or more blocks edited in the first session, and time to a first page with content under 60 seconds at the median; those are the author's proposed targets, not measured results from a shipped change.

**Where it fits his apps.** LYNX SHARE: open with a demo song, a few clips already on the timeline, so the first press of play makes sound, the way FL Studio's demo songs do. Data Pack Builder: a sample pack pre-built and ready to inspect, showing what a finished pack looks like before the user builds one. STELLA: a first profile pre-filled with a small example training job, so the first run is a real run with real numbers. Reblend: a starter scene, one object, one material, one light, Blender-style, so the viewport is never an empty void on first open. In every case the starter content is a real, working artifact, not placeholder text: the user can press the buttons and watch it work before changing anything.

**Watch out.** A gallery of sixteen templates is a choice, not a start: if the user has to decide which template matches a job they do not yet understand, the gallery is just a prettier blank page. Templates that over-deliver structure teach vocabulary the user does not have yet: Notion's Project Tracker hands a first-time note-taker a database with views and rollups, which reads as a different app than the one they came for. Keep the starter small, two or three items, not fifty, and make it obviously an example: labeled as a demo or a sample, deletable in one step, never mixed silently with the user's real work. The example must be real and working, not lorem ipsum, or the user learns nothing by touching it. And always offer a blank start for people who already know the tool: a Skip link costs one click for a returning user and saves a confused new user from the whole decision.
