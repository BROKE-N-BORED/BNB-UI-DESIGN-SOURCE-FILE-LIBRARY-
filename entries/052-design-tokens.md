# 052 — Design tokens

> Entry 052 — added 2026-11-13 (Drop 5: Choices, motion, and craft).

*Every visual decision gets a name, and the name is what the app uses.*

**What it is.** A design token is a named value for one design decision: a color, a spacing step, a font size, a corner radius, a motion duration. The value is stored once, behind the name, and every screen and component uses the name instead of the raw value. Change the value and every surface that uses it changes with it. The term started at Salesforce: Jina Anne coined it with Jon Levine while working on the Lightning Design System, where tokens replaced hard coded hex values and pixel counts. The Design Tokens Community Group calls a token "the single source of truth to name and store a design decision".

Token sets are usually built in three tiers, each pointing at the one below it. Primitive tokens hold raw values with no product meaning: the full palette, the spacing scale, the type sizes. Semantic tokens alias the primitives by role: `color.surface` points at white in light mode and at near black in dark mode, so the name stays the same and only the value switches. Component tokens assign the semantic tokens to specific elements: `button.background` points at `color.accent`. In Figma, tokens are variables: they sit in collections, collections have modes (Light and Dark being the canonical pair), and variables alias each other to build the tiers. The same idea now travels as a plain file. A DESIGN.md file, the format Google Stitch introduced and the awesome-design-md collection applies to real brands, opens with a token block: colors, typography, radii, spacing, then components that reference them by name, as in `backgroundColor: "{colors.canvas}"`.

**Why it matters.** A hex value pasted into twelve components needs twelve edits when the brand color changes. A token needs one. That single edit is the whole point, and it compounds across thirteen apps: a shared token file means a fix to a spacing scale or a text color lands everywhere at once, with no hunt through stylesheets. Modes are the second win. Dark mode, a high contrast variant, or a denser layout stops being a rewrite and becomes a second value set under the same names. The name is the third win: `color.surface` says what the value is for, while `#FFFFFF` says nothing, so anyone opening the file can read intent instead of guessing. Tokens also answer the identity question in this library's own terms. Thirteen apps can share one token *system* and still feel like themselves, because each app keeps its own accent, its own surface, its own radius values. The system is shared; the values are the app's personality. And the cost is nothing: a token file is JSON or YAML text, read once at startup, with zero runtime cost on an 8GB machine with no GPU.

**The key facts.** The format has a stable standard now. The W3C Design Tokens Community Group published the Design Tokens Format Module 2025.10, its first stable version, and the spec states plainly that it is considered stable. It is a Community Group Report, not a W3C Standard and not on the Standards Track, but Figma, Style Dictionary, Tokens Studio, and Terrazzo all read it. The structural rule is one line: an object with a `$value` property is a token, and an object without one is a group. Types are explicit and never guessed: tools must not infer a type from the value. Token files are JSON, with the recommended extensions `.tokens` and `.tokens.json` and the media type `application/design-tokens+json`. Aliases point at another token by path in curly braces. In 2025.10 a color value is an object naming its color space and components, not a bare hex string. On the Figma side, modes are the lever: a Professional plan allows up to 10 modes per collection and Organization up to 20, with no limit on Enterprise. Adoption of the tiers is uneven: zeroheight's design systems report, cited by Modeinspect, finds most teams run primitive and semantic tiers, and about half add a component tier. For a sense of scale, the Vercel DESIGN.md in the awesome-design-md collection runs a spacing scale from 4px to 192px, type from a 12px caption to a 48px display size, and radii from 0 to 9999px, all as named tokens the components reference.

**Where it fits his apps.** STELLA: one token file across its windows, so its accent color, the dark surfaces, and the training graph colors are named once and stay consistent everywhere the app shows them. Fyrn: the model list, the tray indicator, and the chat view share tokens, so the RAM warning color and the pull progress color mean the same thing in all three places. Reblend: the viewport panels and the property sliders share surface and text tokens, and material presets become tokens too, so a preset change is a value change, not a restyle. Yahtzee: the dice, the scorecard, and the felt share one warm palette as tokens, and a dark table variant is a mode switch on the same names, not a second stylesheet.

**What it gets wrong.** Tokens without governance drift, and drift is the failure mode Modeinspect documents best. Five kinds: a token renamed in the design file keeps its old name in code; a value changed in code while the file still shows the old one; a token that exists only in the design file; a token that exists only in code; and a raw hex sitting in a component with no token behind it, which no theme change will ever reach. The fix is mechanical: keep the generated token file in the repo, regenerate it from a fresh export on a branch, and read the drift in the diff. The second failure is sprawl: hundreds of one use tokens are worse than hex, because they add indirection without adding reuse. If a value is used once, it does not need a name. The third is naming by value: a semantic token called `blue-600` breaks the moment dark mode points it at a lighter blue. Modeinspect quotes Atlassian's token docs: choose tokens based on meaning where applicable, not specific values. And tokens are not a design system by themselves. They carry values, not judgment: no components, no guidance, no taste. A token file nobody reads is dead weight, and a token file with no owner rots exactly like the scattered hex it replaced.
