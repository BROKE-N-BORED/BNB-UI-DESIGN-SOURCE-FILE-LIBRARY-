# 020 — Setup checklist

> Entry 020 — added 2026-11-13 (Drop 2: Games, editors, and gadgets).

*three to five steps, then it goes away*

**What it is.** A short list on the home screen that takes a new user
from installed to first result: three to five steps, each one action
with one visible outcome, a progress indicator, and a dismiss button.
Shopify's guidance calls it a setup guide: discrete steps, automatically
marked complete, dismissible if it is not essential. The first step
should already be done when the user first sees the list, because
installing and opening the app were real steps too. When it is done, it
goes away and never comes back.

**Why it feels good.** A blank app asks "what now?" A checklist answers
it, in order, with the end in sight. Each tick is a small win, and the
list gets shorter as you go. The goal-gradient effect is real: in the
classic coffee-card experiment, customers given a 12-stamp card with
two stamps already on it finished faster than customers given a plain
10-stamp card. Starting past zero pulls people forward.

**The numbers.**
- Three to five steps. Shopify's ceiling is five: more steps lead to
  drop-off.
- Userpilot's 2025 benchmark: average checklist completion 19.2 percent,
  median 10.1 percent, across 188 B2B SaaS companies. Four in five
  accounts do not finish, so the design has to work for the ones who
  stop at step two.
- Order by value, not by setup order. The step that produces the first
  result comes before the step that decides how the result will
  eventually be paid for. Defaults break setup order without breaking
  the system.
- The first step is already ticked, honestly: install, connect, and the
  first-screen action are real work the user really did.

**Where it fits his apps.** STELLA (first profile: pick a model, pick
data, run; three steps, the first ticked), Fyrn (models folder, first
pull, first chat), Data Pack Builder (first pack in three steps), MIMIK
(first capture: pick a source, pick a folder, capture).

**Watch out.** A checklist that delays the first result is the wrong
pattern. If the user could get a visible result from one action, that
action belongs on the first screen as a single button, and the checklist
starts after it. Never pre-tick a step the user has not done: a fake
20 percent poisons every other number in the app. And never a modal that
reappears. Dismissed means dismissed, with the steps reachable from an
empty state instead.
